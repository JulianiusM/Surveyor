This second-pass register adds concrete edge cases to the [behavior inventory](BEHAVIOR_INVENTORY.md),
[route inventory](ROUTE_INVENTORY.md) and [test coverage map](TEST_COVERAGE.md). Stable **EC-ID-** identifiers describe
acceptance scenarios; they are not test results. Every test reference below means its assertions were read, not run.
No coverage report or execution result was produced by this audit.

The central distinction is between an account or guest identity, its active profile, overview membership, effective
permission, and lifecycle state. They are separate inputs. A shared SPA component must not infer one from another.
The [cross-cutting edge-case index](EDGE_CASES.md) owns shared transport, draft, picker and upload mechanics; this
register owns the identity and server-state boundaries behind those controls. Unverified SPA acceptance checks remain
explicit gaps; current assertions are linked with their precise boundaries and the paired review owns execution.

## Original focused acceptance gaps and current coverage

Existing tests provide strong persisted archival, membership and relinking evidence. They do not establish a
long-lived client's identity invalidation, universal concurrent edit resolution or periodic refresh policy.
Following the [Testing Guide](../TESTING_GUIDE.md), use the cheapest boundary that proves each new behavior:

- **Frontend/component:** identity-scoped query disposal; old-profile response rejection; independent region state;
  retained dirty drafts; removal of stale permission controls; hidden-region teardown; canonical history and retry.
- **Integration:** any new revision/conditional-write contract; concurrent token consumption if changed; permission
  and membership checks across the write's real locking boundary. Keep existing lifecycle/property transactions.
- **HTTP/browser:** one full-account and guest audience/session journey, one remote profile/permission invalidation,
  one two-client conflicting edit, and the actual supported private-link/return routes. A source fixture with rich
   profile relations is insufficient evidence for a real session's audience qualification.

These are the original source-review gaps, not a claim that every case remains untested. Use the
[current assertion map](TEST_COVERAGE.md#pilot-baseline-to-implementation-assertions) for retained pilot boundaries
and the [paired review](PILOT_PARITY_REVIEW.md) for actual execution, resolutions and remaining limits. Preserve the
original IDs and native evidence; a later focused pass does not certify every identity or unmigrated workflow.

This audit changed documentation only. It ran no application tests, builds, browser sessions, database reset,
migration or data writes. The separate visual baseline is evidence for its recorded capture scenarios only.
